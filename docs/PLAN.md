# 密码本应用策划案（待审批）

- 产品代号：守密（候选名：密盒、岩匣、本密）
- 平台：HarmonyOS，Stage 模型，ArkTS
- 设备：手机、平板、2in1/电脑
- 定位：纯本地、零联网、硬件级加密的密码保险库
- 商业模式：商店侧一次买断；应用内无付费、无订阅、无广告
- 文档状态：v1.0，审批通过前不开发业务代码

## 1. 产品目标

一句话介绍：不联网的密码保险库，所有秘密只留在用户自己的设备中。

产品要解决三个问题：

1. 用户需要保存网站账号、应用密码、银行卡、WiFi、证件、服务器密钥、安全笔记和动态验证码，但不愿把数据上传云端。
2. 普通备忘录没有可靠的加密、认证、剪贴板清理和隐私窗口能力。
3. 专业密码管理器经常以订阅和云同步为核心，本产品则以本地所有权、一次买断和可验证的零联网为核心。

核心承诺：

- 不声明网络权限，不包含网络请求代码、统计 SDK、广告 SDK、云同步、账号系统或远程崩溃上报。
- 密码、TOTP 密钥、备份口令和恢复密钥不离开设备。
- 敏感页面禁止截屏、录屏和投屏。
- 页面文字、图标命名、空状态和提示语均禁止使用 Emoji。
- 手机、平板、2in1/电脑共享同一数据模型和业务代码，但采用适合各自窗口宽度的布局。

## 2. 竞品研究与取舍

### 2.1 苹果密码应用的常见能力

苹果密码应用提供账号密码、Passkey、WiFi 密码、验证码、弱密码提醒、自动填充、跨设备同步和共享组。优势是与系统、浏览器、Face ID/Touch ID 和 iCloud 深度整合；代价是依赖生态账号和云同步。

本产品吸收：

- 清晰分类和快速搜索。
- 强密码生成。
- WiFi 密码管理和二维码分享。
- 离线 TOTP。
- 弱密码、重复密码和陈旧密码检查。
- 使用设备级生物认证保护应用。

本产品不做：

- iCloud 类云同步。
- 家庭共享和在线泄露库查询，因为两者需要联网。
- 未经鸿蒙官方公开能力确认的系统级 Passkey 提供方。

### 2.2 安卓密码管理器的常见能力

Google Password Manager 以系统 Credential Manager、Chrome、自动填充、Passkey 和账号同步为核心。1Password、Bitwarden、KeePass 类产品通常增加自定义字段、附件、TOTP、密码历史、标签、保险库、导入导出和紧急访问。

本产品吸收：

- 多类型条目、自定义字段、标签和收藏。
- 密码生成器、历史版本、回收站。
- 加密导入导出。
- 保险库锁定策略和单条二次认证。
- KeePass 类“离线文件归用户”的理念。

本产品差异：

- 默认且永久零联网，不提供登录和同步开关。
- 使用 HarmonyOS HUKS、Asset Store Kit 和 User Authentication Kit。
- 提供真实保险库与伪装保险库完全隔离的防胁迫模式。
- WiFi 二维码、TOTP、备份均在本地完成。
- 不做“在线泄露检测”；只做本地规则检查，避免虚假宣传。

## 3. 功能范围

### 3.1 首次启动与保险库创建

首次启动为四步引导：

1. 展示“零联网、本地存储、忘记主密码无法恢复”的明确说明。
2. 创建主密码，至少 10 位；提供强度指示和确认输入，不设置默认密码。
3. 选择是否开启设备认证：指纹、人脸或锁屏 PIN，以设备实际支持能力为准。
4. 生成恢复包提示并引导用户立刻创建加密备份。

主密码不是简单保存的字符串。采用高成本 KDF 派生验证材料，并使用随机盐；不得在日志、崩溃信息或数据库中保存明文。

### 3.2 保险库首页

首页提供：

- 搜索：标题、用户名、网址、标签、备注元数据。
- 分类：全部、登录密码、WiFi、银行卡、证件、安全笔记、服务器、TOTP、自定义。
- 智能集合：收藏、最近使用、需要处理、回收站。
- 排序：最近使用、最近修改、名称、创建时间。
- 快捷新增：选择条目类型后进入对应表单。
- 安全概览：弱密码数、重复密码数、长期未更换数，但首页默认只显示摘要，不展示密码。

搜索结果不得泄露密码正文，锁定时清空搜索状态。

### 3.3 条目类型

1. 登录密码：名称、用户名、密码、网站/应用、备注、标签、自定义字段、TOTP、修改历史。
2. WiFi：SSID、密码、安全类型、是否隐藏网络、备注；生成标准 WiFi 二维码。
3. 银行卡：持卡人、卡号、有效期、安全码、开户行、PIN 提示、备注。
4. 证件：类型、姓名、号码、签发地、签发日、到期日、备注。
5. 安全笔记：标题、加密正文、标签。
6. 服务器：主机、端口、用户名、密码、私钥、口令、备注。
7. TOTP：发行方、账号、密钥、位数、周期、算法。
8. 自定义：用户可以新增文本、密码、日期、数字、网址和多行文本字段。

附件首版不加入。附件会显著扩大安全面、内存压力和备份复杂度，待密码核心通过安全审查后再评估。

### 3.4 密码生成器

- 长度 8 至 128，默认 20。
- 可选大写、小写、数字、特殊字符。
- 可排除相似字符和歧义字符。
- 支持“易读口令”模式，用本地词库组合；词库随包安装，不联网。
- 实时熵估算，不能只用颜色表达强弱。
- 生成结果默认不自动复制；用户确认复制后启动清理倒计时。

随机数必须使用 CryptoArchitectureKit 的安全随机源并启用硬件熵，禁止使用 Math.random。

### 3.5 两层安全验证

第一层“应用锁”：

- 可设置每次打开、离开立即、30 秒、1 分钟、5 分钟后锁定。
- 支持指纹、人脸和锁屏 PIN；先查询设备支持能力，再展示选项。
- 认证失败不降级为应用自设的弱 PIN，降级只能到主密码。
- 进入后台立即隐藏内容并切换到隐私遮罩。

第二层“条目锁”：

- 全局开关：查看密码、复制密码、显示 TOTP、导出和备份前是否再次认证。
- 单条覆盖：高敏感条目可强制二次认证，不能被全局关闭覆盖。
- 认证通过可设置 15 秒、30 秒或仅本次操作有效。

### 3.6 离线 TOTP

- 手工输入 Base32 密钥。
- 使用 Scan Kit 扫描 otpauth 二维码；仅在用户主动操作时申请相机能力。
- 支持 SHA1、SHA256、SHA512，6/8 位，30/60 秒。
- 显示环形倒计时、下一个验证码和一键复制。
- TOTP 密钥永不明文显示，除非用户再次认证并明确选择。
- 支持导出到加密备份，不支持明文批量导出。

TOTP 依据标准算法本地生成，使用 CryptoArchitectureKit HMAC 能力。

### 3.7 WiFi 二维码

- 二维码内容使用标准格式：`WIFI:T:类型;S:名称;P:密码;H:隐藏标记;;`。
- SSID、密码中的反斜杠、分号、逗号和冒号做正确转义。
- 使用 HarmonyOS QRCode 组件本地渲染，不生成图片到云端。
- 二维码页默认开启窗口隐私模式；退出即销毁二维码视图。
- 支持调节亮度提示和全屏显示，不主动连接 WiFi。

### 3.8 安全检查

完全离线完成：

- 弱密码：长度、字符集、常见模式和本地弱密码词表。
- 重复密码：使用带密钥的摘要比较，绝不保存可逆的索引明文。
- 相似密码：可选本地规则检查。
- 长期未更换：按用户设置的 90/180/365 天。
- 已过期证件和银行卡提醒：仅应用内展示，不依赖联网。

明确不提供“泄露密码检测”，因为可靠泄露检测需要在线数据源。

### 3.9 伪装与防胁迫

设计为“双保险库”，而不是在真实库上加一个隐藏标签：

- 用户设置独立伪装密码。
- 输入主密码进入真实保险库，输入伪装密码进入伪装保险库。
- 两个库使用不同盐、不同密钥、不同数据库命名空间。
- 伪装库可放入用户自行创建的无敏感样例。
- 界面不显示当前处于伪装模式，也不提供可推断真实库存在的入口。
- 禁止使用“连续输错自动销毁”作为默认功能，避免误删；可选的紧急擦除必须经过多次确认且延迟执行。

限制必须写清：该功能降低临时查看风险，但无法对抗设备取证、恶意系统或用户在已解锁状态下被持续监控。

### 3.10 剪贴板保护

- 复制账号、密码、TOTP 后显示文字倒计时。
- 默认 30 秒，可设 15/30/60 秒或不允许复制。
- 到期仅在剪贴板仍为本应用写入的同一内容时清理，避免误删用户后来复制的内容。
- 应用退到后台时可立即清理。
- 不主动读取其他应用的剪贴板，不申请 READ_PASTEBOARD 权限。
- 使用敏感数据策略阻止剪贴板跨设备传播；若系统版本不支持，向用户明确提示。

### 3.11 加密备份与恢复

备份格式使用自定义版本化容器，例如 `.skvault`：

- 文件头：格式版本、KDF 参数、随机盐、算法标识。
- 密文：条目、设置、TOTP 和历史数据。
- 完整性：AES-256-GCM 认证标签。
- 独立备份密码，不直接复用主密码。
- 导出通过系统文件选择器，由用户决定本地位置。
- 导入先校验文件头、版本、认证标签和空间，再展示条目统计。
- 支持“合并导入”和“替换恢复”；替换前自动生成本地回滚点。
- 不导出 HUKS 设备密钥；备份使用由备份密码派生的可迁移密钥。
- 不提供明文 CSV 导出，降低不可逆泄露风险。

### 3.12 数据生命周期

- 删除先进入加密回收站，默认 30 天后清理。
- “立即永久删除”需要二次认证。
- “清空整个保险库”需要输入指定确认短语和主密码。
- 主密钥销毁后密文不可恢复。
- 数据库迁移必须版本化、可回滚，并覆盖升级测试。

## 4. 页面与视觉设计

### 4.1 视觉方向

风格关键词：克制、安静、可信、精密、高级。

- 浅色：暖白背景、深石墨文字、低饱和墨绿色强调色。
- 深色：近黑蓝背景、柔和灰白文字、冷青绿色强调色。
- 大面积纯色和细微层级，不使用夸张渐变、玻璃拟态或拟物保险箱。
- 圆角统一为 12/16/20vp 三档；阴影仅用于浮层。
- 数字和验证码使用等宽字体，正文使用系统字体。
- 所有图标使用 HarmonyOS Symbol 或自绘矢量图标，禁止 Emoji。
- 密码默认显示为等宽圆点；显隐按钮有清晰文本辅助说明。
- 动效 150 至 240ms，支持系统“减少动态效果”设置。

### 4.2 页面清单

1. 启动隐私遮罩页。
2. 首次使用引导。
3. 创建/验证主密码页。
4. 设备认证页。
5. 保险库首页。
6. 分类和标签页。
7. 搜索页。
8. 新建/编辑条目页。
9. 条目详情页。
10. 密码生成器。
11. TOTP 列表和添加页。
12. WiFi 二维码页。
13. 安全检查中心。
14. 回收站。
15. 备份与恢复。
16. 伪装保险库设置。
17. 安全设置。
18. 外观与无障碍设置。
19. 关于、隐私说明和本地数据说明。

### 4.3 三端适配

使用窗口宽度断点而不是硬编码设备名称：

- 手机窄窗：单栏；底部导航；详情通过页面推进；主要按钮置底。
- 平板中宽窗：左侧分类 + 右侧列表双栏；条目详情以沉浸页或侧边面板打开。
- 2in1/电脑宽窗：分类、条目列表、详情三栏；支持鼠标悬停、右键菜单、键盘焦点、Tab 顺序和快捷键。

电脑端建议快捷键：

- Ctrl+N 新建。
- Ctrl+F 搜索。
- Ctrl+L 立即锁定。
- Ctrl+G 打开密码生成器。
- Esc 隐藏敏感内容或关闭当前浮层。

支持自由窗口、分屏、横竖屏、悬浮窗和窗口尺寸实时变化。窄至手机分屏仍能走完新增、查看、复制和备份流程。

### 4.4 无障碍与可用性

- 字体缩放 100% 至 200% 不截断关键操作。
- 所有按钮有文本或无障碍标签，颜色不是唯一状态表达。
- 最小触控热区 48vp。
- 支持读屏，但密码正文默认不朗读；用户再次认证并明确操作后才可朗读。
- 错误提示说明原因和解决方式，不只显示错误码。
- 全局中文文案不使用 Emoji；自动化扫描资源文件和代码字符串作为发布门禁。

## 5. 技术与安全架构

### 5.1 数据分层

- Asset Store Kit：短敏感数据，例如账号密码、银行卡安全码、TOTP 密钥。官方能力在安全环境中执行 AES-256-GCM，并由通用密钥库保管密钥。
- 加密 RDB：条目元数据、标签、排序、回收站和历史索引；使用 S3 安全等级及自定义加密密钥。
- HUKS：生成和保存不可导出的设备主密钥，设置解密操作的用户认证约束。
- User Authentication Kit：指纹、人脸、锁屏 PIN 认证。
- CryptoArchitectureKit：安全随机数、HMAC、KDF、备份加解密。

任何日志只允许记录操作结果和匿名错误码，不记录标题、用户名、网址、密码、TOTP、二维码内容和文件路径。

### 5.2 密钥结构

- 设备根密钥：HUKS 内生成，不可导出。
- 保险库数据密钥：随机生成，由设备根密钥包裹。
- 主密码密钥：由主密码 + 随机盐 + 高成本 KDF 派生，用于验证和恢复数据密钥。
- 条目密钥：按条目派生或随机生成，减少单点泄露范围。
- 备份密钥：仅由独立备份密码和备份文件盐派生，与设备密钥解耦。

算法参数和格式版本放入文件头，未来可提高 KDF 成本而不破坏旧备份。

### 5.3 运行时防护

- 敏感页面调用 `setWindowPrivacyMode(true)`，禁止截屏、录屏、投屏。
- 进入后台前隐藏界面、清理内存中的明文状态并锁定。
- 明文仅在操作所需的最短时间存在；使用后覆盖可控字节数组。
- 禁止把秘密放入 AppStorage、Preferences、路由参数或全局状态。
- Ability 除系统桌面入口外不对外暴露敏感组件。
- `module.json5` 不声明 INTERNET 权限。
- 发布构建启用混淆、移除调试日志和关闭调试能力。

### 5.4 自动填充边界

HarmonyOS 官方资料明确支持应用登录表单接入系统密码保险箱，但当前检索结果没有足够依据证明普通三方应用可以注册为全系统密码提供方。因此首版不承诺跨应用自动填充。

首版提供安全复制、快速搜索和桌面宽屏快捷操作。若后续官方开放第三方密码提供方 Extension，经过 API 与上架规则验证后再加入，不以非公开接口实现。

## 6. 权限计划

原则：最少权限，能不申请就不申请。

- 网络：不申请。
- 相机：仅用户选择扫描 TOTP 二维码时，通过 Scan Kit 使用；优先采用系统默认扫码界面。
- 剪贴板读取：不申请；本应用只写入并清理自己写入的数据。
- 文件：使用系统文件选择器导入/导出，不申请宽泛存储权限。
- 生物认证：通过系统 User Authentication Kit 拉起标准系统认证界面。
- 通知：首版不申请，避免 TOTP 等秘密出现在通知中心。

设置页提供“权限与隐私”清单，逐项解释用途与当前状态。

## 7. 商业与上架方案

应用内没有购买、会员、订阅、广告和试用墙。计划在应用市场发布配置中设置一次买断价格，购买后下载完整功能版本。

发行配置是否支持某设备品类的付费下载，以提交时 AppGallery Connect 实际开放能力为准；这不会改变应用代码和零联网设计。如果商店暂不提供该设备品类的付费下载，只调整发行方式，不在应用内临时加入联网支付。

商店材料包括：

- 名称、图标、一句话简介、详细说明、关键词和分级。
- 手机、平板、2in1/电脑三套真实截图。
- 隐私标签选择“不收集用户数据”。
- 可公开访问的隐私政策网页；网页只用于应用市场审核和用户查阅，应用运行不请求该网页。
- 用户协议、电子版权材料和软件著作权材料（按发行地区要求准备）。
- 安全说明：算法、离线边界、遗忘密码不可恢复、备份责任。

不得宣传“绝对安全”“无法破解”。使用可验证表述，例如“不声明网络权限”“密钥由 HUKS 保存”“敏感窗口禁止系统截屏”。

## 8. 质量与发布门槛

达到“可上架”必须同时满足：

1. 单元测试：KDF、加解密、TOTP 标准向量、WiFi 转义、密码评分、备份格式和数据库迁移。
2. 集成测试：首次创建、锁定/解锁、认证取消、增删改查、回收站、备份恢复、伪装库隔离。
3. 故障测试：进程被杀、锁屏、低存储、备份中断、错误密码、损坏文件、系统时间变化。
4. 多端测试：Phone、Tablet、2in1/PC；横竖屏、自由窗口、分屏、深浅色和大字体。
5. 安全测试：无网络权限、无明文落盘、无敏感日志、截录屏阻断、剪贴板清理、随机数来源、密钥不可导出。
6. 静态检查：ArkTS Linter 零错误；资源与代码中 Emoji 扫描零命中。
7. 性能：1000 条条目下搜索流畅；冷启动不展示明文；大备份不阻塞 UI。
8. 可访问性：读屏、键盘导航、焦点顺序、对比度和 200% 字体。
9. 发布构建：签名、混淆、版本升级、隐私资料、截图和商店描述全部完成。

## 9. 开发阶段

审批通过后按以下顺序开发，每一阶段独立验收：

1. 工程基础：新业务分支、设计令牌、响应式导航、数据库迁移框架、日志红线。
2. 安全内核：HUKS、Asset Store、主密码、用户认证、生命周期锁定。
3. 核心保险库：条目模型、增删改查、分类、搜索、收藏、回收站。
4. 专业能力：生成器、TOTP、WiFi 二维码、安全检查、剪贴板保护。
5. 高级安全：单条二次认证、伪装库、加密备份恢复。
6. 三端精修：手机、平板、2in1/电脑布局、鼠标键盘与多窗。
7. 发布收尾：安全审计、自动化测试、性能、无障碍、商店素材和签名包。
