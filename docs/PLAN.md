## 1. 产品目标

一句话介绍：不联网的密码保险库，所有秘密只留在用户自己的设备中。

产品要解决三个问题：

1. 用户需要保存网站账号、应用密码、银行卡、WiFi、证件、服务器密钥、安全笔记和动态验证码，但不愿把数据上传云端。
2. 普通备忘录没有可靠的加密、认证、剪贴板清理和隐私窗口能力。
3. 专业密码管理器经常以订阅和云同步为核心，本产品则以本地所有权、一次买断和可验证的零联网为核心。

核心承诺：

- 不声明网络权限，不包含网络请求代码、统计 SDK、广告 SDK、云同步、账号系统或远程崩溃上报。
- 密码、TOTP 密钥、备份口令和恢复密钥不离开设备。
- 敏感页面默认禁止截屏、录屏和投屏；该保护可由用户在设置中关闭。
- 隐私保护功能一律“默认开启、可以关闭”，应用不强制用户接受任何一项。
- 页面文字、图标命名、空状态和提示语均禁止使用 Emoji。
- 手机、平板、2in1/电脑共享同一数据模型和业务代码，但采用适合各自窗口宽度的布局。

## 2. 竞品研究与取舍

### 2.1 苹果密码应用的常见能力

苹果密码应用提供账号密码、Passkey、WiFi 密码、验证码、弱密码提醒、自动填充、跨设备同步和共享组。优势是与系统、浏览器、Face ID/Touch ID 和 iCloud 深度整合；代价是依赖生态账号和云同步。

本产品吸收：

- 清晰分类和快速搜索。
- 强密码生成。
- WiFi 密码管理和二维码分享。
- 离线 TOTP。
- 弱密码、重复密码和陈旧密码检查。
- 使用设备级生物认证保护应用。

本产品不做：

- iCloud 类云同步。
- 家庭共享和在线泄露库查询，因为两者需要联网。
- 未经鸿蒙官方公开能力确认的系统级 Passkey 提供方。

### 2.2 安卓密码管理器的常见能力

Google Password Manager 以系统 Credential Manager、Chrome、自动填充、Passkey 和账号同步为核心。1Password、Bitwarden、KeePass 类产品通常增加自定义字段、附件、TOTP、密码历史、标签、保险库、导入导出和紧急访问。

本产品吸收：

- 多类型条目、自定义字段、标签和收藏。
- 密码生成器、历史版本、回收站。
- 加密导入导出。
- 保险库锁定策略和单条二次认证。
- KeePass 类“离线文件归用户”的理念。

本产品差异：

- 默认且永久零联网，不提供登录和同步开关。
- 使用 HarmonyOS HUKS、Asset Store Kit 和 User Authentication Kit。
- 提供真实保险库与伪装保险库完全隔离的防胁迫模式。
- WiFi 二维码、TOTP、备份均在本地完成。
- 不做“在线泄露检测”；只做本地规则检查，避免虚假宣传。

## 3. 功能范围

### 3.1 首次启动与保险库创建

首次启动为四步引导：

1. 展示“零联网、本地存储、忘记主密码无法恢复”的明确说明。
2. 选择解锁方式：不加额外应用锁、应用主密码、设备认证（指纹/人脸/锁屏 PIN）。用户可以跳过应用锁，数据仍保持硬件加密。
3. 如果用户选择应用主密码，则至少 10 位，提供强度指示和确认输入，不设置默认密码。
4. 生成恢复包提示并引导用户立刻创建加密备份。

数据加密与“打开应用是否输密码”分离：保险库始终由 HUKS 设备密钥加密；应用锁只是访问门槛，可以关闭。用户设置主密码时，采用高成本 KDF 派生验证材料并使用随机盐；不得在日志、崩溃信息或数据库中保存明文。

### 3.1.1 密钥包裹结构（“忘记密码怎么办”的技术根基）

真正加解密所有条目的是一把随机生成的“数据主密钥（DEK）”。DEK 不直接依赖某一个密码，而是被多把“钥匙”分别包裹，存多份密文副本。任意一把钥匙可用，就能解开 DEK、进而解开全部数据；所有钥匙都失效，数据才不可恢复。

DEK 的包裹副本包括：

1. 设备钥匙副本：用 HUKS 设备根密钥包裹，存本机，并绑定用户认证约束。设备正常、应用锁允许时用它解开，用户日常无感。
2. 主密码钥匙副本：即“App 内置密码”，仅当用户启用时创建，用主密码经高成本 KDF 派生的密钥包裹。
3. 私密问题钥匙副本：用户自定义一个“私密问题 + 答案”，用答案经 KDF 派生的密钥包裹一份 DEK；这份副本再叠加一层 HUKS 设备密钥保护，使答案无法被离线暴力破解（必须在本机、设备解锁状态下才可用）。
4. 备份钥匙副本：不在设备内，而是存在用户导出的 `.zvault` 文件里，由导出密码派生（见 3.12）。

这样“忘记某一个”不等于“数据全没”：只要还有任意一把钥匙有效，就能重新设置其他钥匙。

### 3.1.2 忘记密码 / 无法解锁的完整处理逻辑

先分清两层密码：
- 第一层是**手机系统认证**（指纹、人脸、锁屏 PIN），归系统管，忘了只能在系统里重置，本应用无能为力。
- 第二层是**App 内置密码**（主密码），这是本应用自己的密码，忘了必须有明确、安全、不过度麻烦的重置办法，绝不允许“忘了就一键清空”。

忘记 App 内置密码时，提供两条重置路径，用户在设置中至少启用一条（默认启用路径一）：

路径一：双重设备验证重置（默认）。
1. 解锁页选择“忘记内置密码”。
2. 要求连续通过**两种不同的系统认证因子**，例如“指纹 + 锁屏密码”或“人脸 + 锁屏密码”，两者都通过才算数；只过一种不放行。
3. 全部通过后用设备钥匙副本解开 DEK，允许直接设置新的内置密码，无需旧密码。
4. 设备本身不支持两种因子时，此路径自动置灰并提示改用路径二或备份恢复。

路径二：自定义私密问题重置（可选开启）。
1. 用户在设置中**自己写问题、自己写答案**，不使用“你喜欢的水果”这类预设题；鼓励写只有自己知道、且不随喜好变化的问题。
2. 解锁页选择“用私密问题重置”，答案正确即解开私密问题钥匙副本，允许设置新的内置密码。
3. 答案校验带失败次数限制与递增等待，防止他人反复猜测；答案在应用内始终以密文保存，永不明文展示。

两条路径都走不通，但有 `.zvault` 备份和导出密码时：
1. 首启页或解锁页提供“从备份恢复”。
2. 选择 `.zvault`，输入导出密码，走 3.12 的导入替换流程。
3. 恢复到导出那一刻的数据；导出之后新增的内容无法找回。

以上全都没有（内置密码、双重验证、私密问题、备份都没有）：
1. 明确告知：按零知识设计，本机数据在技术上不可解密，任何人都无法恢复，这是安全特性不是缺陷。
2. 提供“清空并重新初始化”，需要输入固定确认短语并二次确认，销毁本机密文与所有钥匙副本，回到首次引导。
3. 全程不提供任何“客服找回”“上传找回”入口，避免钓鱼与误导。

配套要求：
- 首次引导启用内置密码后，强制出现一次“设置重置方式（双重验证或私密问题）并建议立即创建备份”的提醒，用户可跳过但必须明确点击“我已了解风险”。
- 更换内置密码、私密问题、导出密码时都只是重新包裹 DEK，不重新加密全部条目，保证大数据量下也快速完成。
- 修改任一钥匙后，旧钥匙包裹副本立即覆盖删除。
- 重置内置密码属于高敏感操作，过程本身也受“双重验证或私密问题”保护，防止捡到已解锁手机的人随意改密码。

### 3.2 保险库首页

首页提供：

- 搜索：标题、用户名、网址、标签、备注元数据。
- 分类：全部、登录密码、WiFi、银行卡、证件、安全笔记、服务器、TOTP、自定义。
- 智能集合：收藏、最常用、最近使用、最近添加、需要处理、回收站。
- 排序方式：使用频率（最常用优先）、最近使用、最近修改、创建时间、名称拼音，升降序均可。
- 按日期分组视图：今天、本周、本月、更早；可切换按创建日期或修改日期分组。
- 使用统计：每条记录本地保存使用次数与最近使用时间，仅用于排序和“最常用”集合，永不外传；统计可在设置中清零。
- 快捷新增：选择条目类型后进入对应表单。
- 安全概览：弱密码数、重复密码数、长期未更换数，但首页默认只显示摘要，不展示密码。

搜索结果不得泄露密码正文，锁定时清空搜索状态。

### 3.3 条目类型

1. 登录密码：名称、用户名、密码、网站/应用、备注、标签、自定义字段、TOTP、修改历史。
2. WiFi：SSID、密码、安全类型、是否隐藏网络、备注；生成标准 WiFi 二维码。
3. 银行卡：持卡人、卡号、有效期、安全码、开户行、PIN 提示、备注。
4. 证件：类型、姓名、号码、签发地、签发日、到期日、备注。
5. 安全笔记：标题、加密正文、标签。
6. 服务器：主机、端口、用户名、密码、私钥、口令、备注。
7. TOTP：发行方、账号、密钥、位数、周期、算法。
8. 自定义：用户可以新增文本、密码、日期、数字、网址和多行文本字段。
9. 日记本：带独立密码的私人日记（含录音、配图），见 3.15。

日记本是本次新增的重点内容类型，详见 3.15。通用文件保管箱已决定不做，原因见 3.16。

条目管理细节：

- 支持批量选择、批量移动分类、批量加标签、批量移入回收站。
- 支持自定义分类、颜色标记（同时显示文字，不能只靠颜色识别）和置顶。
- 支持用户名、网址、备注、自定义字段的局部匹配；密码正文不进入全文索引。
- 支持同一服务保存多个账号，列表明确显示用户名避免误选。
- 条目修改前保留加密历史版本，可查看差异并恢复。
- 支持从 Apple/Chrome 通用 CSV、Bitwarden JSON 和 KeePass XML 导入；解析、映射、去重全在本地完成。导入明文文件后明确提醒用户删除源文件。
- 不提供明文导出，只允许加密备份，避免用户误把完整密码库暴露到普通文件。

### 3.3.1 条目基础操作（增 / 查 / 改 / 删）

这些是最基础也必须做扎实的操作，逐条明确：

新增：
- 从首页快捷按钮或分类页进入，先选类型再填表单。
- 必填项校验（如登录密码至少要有名称或用户名之一），未填完整给出即时提示。
- 表单有未保存内容时返回，弹出“放弃修改/继续编辑”确认。
- 保存即加密写入，成功后回到列表并高亮新条目。

查看：
- 详情页默认隐藏密码、安全码、私钥等敏感字段，显示为圆点，点击“显示”才明文展示。
- 是否需要在查看/复制前二次验证，跟随 3.5 条目锁设置。
- 单字段一键复制，复制后按剪贴板设置倒计时清理。
- 展示创建时间、修改时间、最近使用时间和使用次数。

编辑 / 修改密码：
- 详情页“编辑”进入同一套表单，预填现有值。
- 改动密码字段时，旧值自动存入加密历史版本，可回看和恢复。
- 可对单条修改二次认证要求、置顶、收藏、分类和标签。
- 保存时更新“修改时间”，合并导入按此判断新旧。
- 提供“修改历史”入口，展示历次变更时间与差异，敏感值仍默认隐藏。

删除：
- 默认软删除进回收站（3.13），可恢复。
- 回收站内可“恢复”或“永久删除”；永久删除需按条目锁设置二次确认。
- 支持批量删除；批量永久删除额外确认数量。
- 关闭回收站时删除即为直接永久删除，并在关闭该功能时明确提示这一后果。

### 3.4 密码生成器

- 长度 8 至 128，默认 20。
- 可选大写、小写、数字、特殊字符。
- 可排除相似字符和歧义字符。
- 支持“易读口令”模式，用本地词库组合；词库随包安装，不联网。
- 实时熵估算，不能只用颜色表达强弱。
- 生成结果默认不自动复制；用户确认复制后启动清理倒计时。

随机数必须使用 CryptoArchitectureKit 的安全随机源并启用硬件熵，禁止使用 Math.random。

### 3.5 两层安全验证

原则：两层验证都是用户的选择，不是应用的强制。每一层都可以在设置中独立打开或关闭；关闭时应用给出一次风险说明，但尊重用户决定。不可关闭的是底层静态数据加密，但它不产生任何交互弹窗。

第一层“应用锁”（可开可关）：

- 可设置每次打开、离开立即、30 秒、1 分钟、5 分钟后锁定，或关闭应用锁。
- 支持指纹、人脸和锁屏 PIN；先查询设备支持能力，再展示选项。
- 认证失败不降级为应用自设的弱 PIN，降级只能到主密码。
- 进入后台立即隐藏内容并切换到隐私遮罩。

第二层“条目锁”（可开可关）：

- 全局开关：查看密码、复制密码、显示 TOTP、导出和备份前是否再次认证，四项独立设置。
- 单条覆盖：用户可给某条目单独设置“总是要求验证”或“跟随全局”。
- 认证通过可设置 15 秒、30 秒或仅本次操作有效。

### 3.6 离线 TOTP

- 手工输入 Base32 密钥。
- 使用 Scan Kit 扫描 otpauth 二维码；仅在用户主动操作时申请相机能力。
- 支持 SHA1、SHA256、SHA512，6/8 位，30/60 秒。
- 显示环形倒计时、下一个验证码和一键复制。
- TOTP 密钥永不明文显示，除非用户再次认证并明确选择。
- 支持导出到加密备份，不支持明文批量导出。

TOTP 依据标准算法本地生成，使用 CryptoArchitectureKit HMAC 能力。

### 3.7 WiFi 二维码

- 二维码内容使用标准格式：`WIFI:T:类型;S:名称;P:密码;H:隐藏标记;;`。
- SSID、密码中的反斜杠、分号、逗号和冒号做正确转义。
- 使用 HarmonyOS Scan Kit `generateBarcode.createBarcode` 在本地生成 `PixelMap`，不生成图片到云端。
- 二维码页默认开启窗口隐私模式；退出即销毁二维码视图。
- 支持调节亮度提示和全屏显示，不主动连接 WiFi。

### 3.8 快速二维码

这是全局工具，不局限于 WiFi 条目。用户在应用任何主要页面都能快速打开：

- 手机：底部导航中央“生成”按钮；条目详情的“生成二维码”操作。
- 平板：左侧导航条固定入口；条目右键/长按菜单入口。
- 2in1/电脑：顶部工具栏“快速二维码”、右键菜单，以及 `Ctrl+Q` 快捷键。

支持内容：

1. 任意文本。
2. 网站 URL。
3. WiFi 连接信息。
4. 电话号码、短信文本、电子邮箱。
5. 联系人 vCard。
6. 当前密码条目的用户名、网址或用户明确选择的字段。

安全与体验：

- 默认不自动把密码放进二维码；选择密码字段时再次明确确认，是否二次认证跟随条目锁设置。
- 内容为空、超过 Scan Kit 容量、尺寸过小或对比度不足时在生成前拦截并给出可操作提示。
- 可选纠错等级、码图尺寸、前景/背景色；自动检测对比度，禁止生成难以扫描的配色。
- 生成记录默认不保存；用户可选择“加密保存到保险库”。
- 页面退出立即释放 `PixelMap`，不写入相册或缓存；只有用户主动选择“保存图片”才通过系统文件选择器导出 PNG。
- 全程使用本地 Scan Kit，不声明网络权限。

模拟器保护是硬性发布门槛：

- HarmonyOS 官方文档明确说明 Scan Kit 码图生成能力暂不支持模拟器，调用时返回 “The capability is not supported on the emulator at this time.”。
- 当前公开 API 没有可靠的通用“是否模拟器”标志，所以不能靠机型字符串猜测；采用更稳妥的能力调用结果检测。
- 二维码服务统一封装 `QrCodeService`，同步 `try/catch`、Promise `catch`、回调错误和组件生命周期取消四层处理，不允许异常穿透到页面导致闪退。
- 首次进入二维码工具时先执行无敏感内容的能力探测。收到官方“不支持模拟器”错误后缓存本次运行状态，不再调用生成接口。
- 模拟器弹窗文案：“当前为模拟器环境，暂不支持生成二维码。请连接 HarmonyOS 真机测试此功能。”按钮为“知道了”。
- 不支持时保留内容编辑和复制，禁用“生成”按钮；不能显示空白二维码，也不能让应用退出。
- 真机生成失败时显示“二维码生成失败，请调整内容后重试”，并记录非敏感错误码，不记录二维码内容。

### 3.9 安全检查

完全离线完成：

- 弱密码：长度、字符集、常见模式和本地弱密码词表。
- 重复密码：使用带密钥的摘要比较，绝不保存可逆的索引明文。
- 相似密码：可选本地规则检查。
- 长期未更换：按用户设置的 90/180/365 天。
- 已过期证件和银行卡提醒：仅应用内展示，不依赖联网。

明确不提供“泄露密码检测”，因为可靠泄露检测需要在线数据源。

### 3.10 伪装与防胁迫

设计为“双保险库”，而不是在真实库上加一个隐藏标签：

- 用户设置独立伪装密码。
- 输入主密码进入真实保险库，输入伪装密码进入伪装保险库。
- 两个库使用不同盐、不同密钥、不同数据库命名空间。
- 伪装库可放入用户自行创建的无敏感样例。
- 界面不显示当前处于伪装模式，也不提供可推断真实库存在的入口。
- 禁止使用“连续输错自动销毁”作为默认功能，避免误删；可选的紧急擦除必须经过多次确认且延迟执行。

限制必须写清：该功能降低临时查看风险，但无法对抗设备取证、恶意系统或用户在已解锁状态下被持续监控。

### 3.11 剪贴板保护

- 复制账号、密码、TOTP 后显示文字倒计时。
- 默认 30 秒，可设 15/30/60 秒或关闭自动清理。
- 到期仅在剪贴板仍为本应用写入的同一内容时清理，避免误删用户后来复制的内容。
- 应用退到后台时可立即清理。
- 不主动读取其他应用的剪贴板，不申请 READ_PASTEBOARD 权限。
- 使用敏感数据策略阻止剪贴板跨设备传播；若系统版本不支持，向用户明确提示。

### 3.12 设置中的加密导出与导入

入口固定放在“设置 > 数据管理 > 导出与导入”。这个功能既是备份，也是电脑、平板和手机之间的手动离线迁移方案，不是云同步。

导出流程：

1. 用户选择“导出加密保险库”。
2. 设置独立的导出密码并再次确认；允许用户主动选择复用应用主密码，但不默认复用。
3. 应用在内存中序列化完整保险库，通过系统文件选择器保存为 `.zvault` 文件。
4. 导出完成后显示条目数量、文件版本、校验状态和保存位置，不显示任何秘密内容。

`.zvault` 版本化容器：

- 明文文件头只含固定魔数 `ZVLT`、格式版本、KDF 算法与成本参数、随机盐、随机 nonce；不含条目名称、用户名、数量或设备信息。
- 导出密码通过 PBKDF2-HMAC-SHA256 和随机盐派生 256 位备份密钥；迭代成本在目标设备首次运行时校准到合理耗时，并设置安全下限。
- 全部业务内容使用 AES-256-GCM 加密并校验完整性。
- 密文包含条目所有字段、分类、标签、收藏、创建/修改日期、使用次数、最近使用时间、历史版本、TOTP、WiFi、日记正文和通用设置等**文字与结构化数据**。
- 录音、配图这类二进制媒体**不打包进 `.zvault`**，避免文件过大。它们走“普通导出”：用户主动选择后，通过系统文件选择器把解密后的原格式音频/图片单独保存到指定位置；导出后的普通文件不再受本应用加密保护，去向由用户负责，界面对此有一次明确提示。
- 换句话说：**文字 = 加密导出（`.zvault`）；照片、录音 = 普通导出（原始文件）**。
- 不包含 HUKS 设备密钥、指纹/人脸状态和设备锁设置；这些安全设置在新设备上重新选择。

`.zvault` 是不是“真加密”（可验证保证）：

- 加密算法用 HarmonyOS 官方 CryptoArchitectureKit 的 AES-256-GCM，密钥由导出密码经 PBKDF2-HMAC-SHA256 + 随机盐派生；不是改后缀、不是压缩包加壳、不是 Base64 或简单异或“伪加密”。
- 文件里除了必要的明文文件头（魔数、版本、KDF 参数、随机盐、随机 nonce）以外，**全部是密文加 GCM 认证标签，没有任何可读的账号、密码、日记或标题**。
- 用三个客观测试证明“真加密”，作为发布门槛（见 8.2）：
  1. 二进制检查：导出后用十六进制查看文件，全局搜索样本里的明文密码、用户名、日记片段，必须“零命中”。
  2. 错误密码必败：用错误导出密码解密必定失败并报“密码不正确或文件已损坏”，绝不出现部分明文。
  3. 篡改必败：改动密文任意一字节，GCM 认证校验必定失败，拒绝导入。
- 诚实边界：加密强度取决于导出密码强度。密码太弱时，他人拿到文件仍可能离线暴力猜解，这是所有基于口令加密的共性；因此设置导出密码时给出强度提示，但不替用户强制。
- 文件写入使用临时文件 + 完成后原子重命名；失败时删除临时文件。
- 序列化过程不产生明文中间文件。

导入流程：

1. 通过系统文件选择器只选择 `.zvault`。
2. 先检查魔数、版本、长度上限和结构，再请求导出密码。
3. 密码错误、文件损坏和认证标签错误统一提示“密码不正确或文件已损坏”，不泄露内部判断。
4. 解密成功后展示来源版本、条目数、分类数和冲突数。
5. 提供“完整替换”和“合并导入”：
   - 完整替换：手机导入电脑导出的文件后，获得相同的名称、密码、字段、分类、日期、收藏、频率、TOTP 和历史。
   - 合并导入：按稳定条目 ID 识别同一记录；较新修改版本优先，冲突时让用户逐条选择或全部保留副本。
6. 数据库操作在单个事务中完成；失败全部回滚，不留下半份保险库。
7. 替换前生成仅在当前设备可用的加密回滚点，确认成功后按保留策略清理。

导入导出兼容性规则：

- 同一个 `.zvault` 文件必须能在 Phone、Tablet、2in1/PC 之间互相导入。
- 新版本必须向后读取旧格式；旧版本遇到新格式要明确提示升级，不能崩溃。
- 文件大小、条目数量、字段长度均设安全上限，防止恶意文件耗尽内存。
- 不提供明文 CSV 导出，降低不可逆泄露风险。

### 3.13 数据生命周期

- 删除先进入加密回收站，默认 30 天后清理（时长可设，回收站可关闭改为直接删除）。
- “立即永久删除”默认需要二次认证（跟随条目锁开关）。
- “清空整个保险库”需要输入指定确认短语和主密码。
- 主密钥销毁后密文不可恢复。
- 数据库迁移必须版本化、可回滚，并覆盖升级测试。

### 3.15 加密日记本

日记本是独立于密码条目的一块功能，主打“只有自己能打开的私人日记”。

结构：
- 用户可创建一个或多个日记本；每个日记本可单独设置“打开需要验证”开关，用设备认证或内置密码守护，默认开启。
- 日记本本身仍受 App 锁和底层加密保护；日记本密码是第二道门，可开可关，可与其他日记本各自独立。
- 日记本内是按日期排列的日记条目。

单篇日记：
- 左上角实时显示日期，默认当天；用户可点击改成任意日期，用于补记。
- 字段：日期、标题（可空）、正文（富文本：加粗、列表、引用、分割线）、心情/天气/标签（可选）、录音、配图。
- 正文、录音、配图全部加密存储，和密码条目同一套密钥体系。这些是日记自带的内容，不是通用文件管理功能（通用文件保管箱不做，见 3.16）。
- 支持编辑、修改历史、软删除进回收站，与 3.3.1 一致。

日记录音：
- 仅在用户点击“录音”时，通过系统弹窗申请麦克风权限；拒绝则禁用录音但不影响其他功能。
- 使用 HarmonyOS AVRecorder 本地录制，录完立即加密保存到应用私有空间，不写入公共媒体库、不联网。
- 应用内解密播放，进度、暂停、删除齐全。
- 录音时如触发锁定或进入后台，安全停止并保存已录部分，不丢现场。

日记配图：
- 通过系统图库选择器（PhotoViewPicker）选图，复制进应用私有空间后加密保存，不申请相册读写权限。
- 应用内解密查看。
- 录音和配图的导出方式见 3.12：走“普通导出”，即导出为原格式的音频/图片文件，不做加密封装。

日记美观度：
- 采用“日记本”版式：顶部大号日期、纸张质感的浅底、舒适行距、可选衬线正文字体；深色下用护眼低亮底。
- 保持全局克制风格，不使用花哨贴纸和 Emoji；情绪用自绘图标或文字表达。
- 三端适配：手机整页书写；平板左侧日期时间线 + 右侧正文；电脑左侧日记本列表、中间时间线、右侧编辑区。

### 3.16 关于通用文件保管箱（已决定不做）

经确认，不做通用文件保管箱 / 文件管理器。原因：

- 华为文件管理已自带“文件保险箱 / 保密柜”，可把系统文件移入加锁，本应用无需重复造。
- 鸿蒙沙箱机制下，应用无法静默删除用户系统里的原文件，做不到“导入后自动清除原件”，容易给用户错误的安全预期。
- 任意格式的应用内查看器工作量大、上架风险高，会拖累核心体验。

因此“存文件”这类需求引导用户使用系统自带文件保险箱；本应用只在日记内提供录音和配图这类内容型媒体（见 3.15）。

### 4.1 视觉方向

风格关键词：克制、安静、可信、精密、高级。

- 浅色：暖白背景、深石墨文字、低饱和墨绿色强调色。
- 深色：近黑蓝背景、柔和灰白文字、冷青绿色强调色。
- 大面积纯色和细微层级，不使用夸张渐变、玻璃拟态或拟物保险箱。
- 圆角统一为 12/16/20vp 三档；阴影仅用于浮层。
- 数字和验证码使用等宽字体，正文使用系统字体。
- 图标方案不依赖 SVG：界面功能图标优先使用系统 SymbolGlyph 图标库（`$r('sys.symbol.*')`，不是项目 SVG 文件，可变色并随字号缩放）；系统库没有的品牌/分类图标使用多密度 PNG 资源。
- 应用桌面图标严格使用 HarmonyOS 官方双层图标：前景和背景分别为 1024×1024 PNG，正方形、无预切圆角、背景无透明像素；手机、平板和电脑分别真机检查遮罩与动效。禁止 Emoji。
- 密码默认显示为等宽圆点；显隐按钮有清晰文本辅助说明。
- 动效 150 至 240ms，支持系统“减少动态效果”设置。

细节打磨清单（发布前逐项核对）：

- 间距使用 4vp 基准网格：4/8/12/16/24/32。
- 字号阶梯：大标题 30、页面标题 24、卡片标题 18、正文 16、辅助 14、说明 12，全部随系统字体缩放。
- 列表项统一 72vp 高（紧凑模式 56vp），左图标、中双行文本、右操作区对齐。
- 每个列表、搜索、分类都有设计过的空状态插画位与引导按钮，插画用 PNG。
- 加载、保存、认证、复制均有即时状态反馈；按钮防连点。
- 卡片按压有 0.97 缩放反馈；页面转场用系统 Navigation 转场。
- 深浅色下逐页核对对比度，禁止纯黑#000 文字压深色背景。

### 4.3 三端适配

手机端和电脑端窗口尺寸差异很大，不能把同一页面简单缩放。按窗口宽度断点设计三套布局，开发时逐页实现：

| 断点 | 窗口宽度 | 典型设备 | 主布局 |
| --- | --- | --- | --- |
| sm | 小于 600vp | 手机、手机分屏 | 单栏 |
| md | 600 至 839vp | 平板竖屏、悬浮窗 | 双栏 |
| lg | 大于等于 840vp | 平板横屏、2in1/电脑 | 三栏 |

- 手机窄窗：单栏；底部导航分为保险库、安全检查、设置；详情通过页面推进；主按钮置底方便拇指操作；搜索从顶部展开。
- 平板中宽窗：左侧分类栏 + 右侧列表；条目详情以侧滑面板打开；底部导航改为左侧窄导航条。
- 2in1/电脑宽窗：分类、条目列表、详情三栏常驻；顶部工具栏常显搜索、新建和锁定；支持鼠标悬停提示、右键菜单、键盘焦点环和 Tab 顺序。

## 5. 技术与安全架构

### 5.1 数据分层

- Asset Store Kit：短敏感数据，例如账号密码、银行卡安全码、TOTP 密钥。官方能力在安全环境中执行 AES-256-GCM，并由通用密钥库保管密钥。
- 加密 RDB：条目元数据、标签、排序、回收站和历史索引；使用 S3 安全等级及自定义加密密钥。
- HUKS：生成和保存不可导出的设备主密钥，设置解密操作的用户认证约束。
- User Authentication Kit：指纹、人脸、锁屏 PIN 认证。
- CryptoArchitectureKit：安全随机数、HMAC、KDF、备份加解密。

任何日志只允许记录操作结果和匿名错误码，不记录标题、用户名、网址、密码、TOTP、二维码内容和文件路径。

### 5.2 密钥结构

- 数据主密钥 DEK：随机生成，是真正加解密条目的密钥；被下列多把钥匙分别包裹，存多份密文副本（见 3.1.1）。
- 设备钥匙：HUKS 设备根密钥，包裹一份 DEK，存本机、不可导出，并绑定用户认证约束（双重验证走这条路径解开 DEK）。
- 可选主密码钥匙：用户启用应用内置密码时，由主密码 + 随机盐 + 高成本 KDF 派生，包裹一份 DEK；关闭时不创建该副本。
- 私密问题钥匙：由用户自定义答案 + 随机盐派生，包裹一份 DEK，并叠加 HUKS 设备密钥保护，防离线暴力破解。
- 备份钥匙：由独立备份密码和备份文件盐派生，包裹进 `.zvault`，与设备密钥解耦。
- 更换内置密码、私密问题或备份密码只重新包裹 DEK，不重新加密全部条目；旧副本立即覆盖删除。

算法参数和格式版本放入文件头，未来可提高 KDF 成本而不破坏旧备份。

### 5.3 运行时防护

- 敏感页面调用 `setWindowPrivacyMode(true)`，禁止截屏、录屏、投屏；该行为跟随用户设置，关闭后不再启用隐私窗口。
- 进入后台时始终清理不再需要的明文内存；是否显示隐私遮罩、是否锁定分别跟随用户开关。
- 明文仅在操作所需的最短时间存在；使用后覆盖可控字节数组。
- 禁止把秘密放入 AppStorage、Preferences、路由参数或全局状态。
- Ability 除系统桌面入口外不对外暴露敏感组件。
- `module.json5` 不声明 INTERNET 权限。
- 发布构建启用混淆、移除调试日志和关闭调试能力。

### 5.4 跨应用自动填充与“登录成功自动保存”

目标体验：用户在网站或其他应用中输入账号密码并成功登录后，系统询问是否保存到本密码本；下次登录时可从本密码本自动填充。

官方能力查证结果：

- HarmonyOS 公开文档确认登录表单可以接入系统密码保险箱，`autoFillManager` 支持由登录应用主动触发保存。
- 但截至当前 API 6.1.1(24) 的公开三方应用文档，没有找到允许普通三方密码管理器注册成系统级“密码提供方”的 `AutoFillExtensionAbility`。
- `autoFillManager` 是登录应用调用系统保存能力，不代表另一个普通应用可以监听所有应用的登录成功事件。
- 浏览器或其他应用的登录是否成功属于对方应用内部状态；在不使用辅助功能、不读取界面、不注入代码的前提下，本应用不能自行判断。

因此不能假装实现，更不能通过无障碍监听、悬浮窗抓取或私有接口绕过系统，这会破坏隐私、违反零权限原则并影响上架。

本项目的完整实现策略：

1. 先实现密码库内的快速查找、安全复制和 URI/应用标识关联。
2. 实现“从分享面板保存”入口：其他应用允许分享文本时，用户主动分享到本应用并确认字段。
3. 实现“手动保存登录”快捷页，自动识别用户粘贴的账号、网址和密码字段，但保存前必须确认。
4. 在代码中预留 `CredentialProviderAdapter` 抽象层，并为系统能力做运行时检测。
5. 一旦目标 HarmonyOS SDK/应用市场正式开放三方密码提供方接口，就在同一完整版本中接入；只有真机验证和审核规则确认后才启用。
6. 不承诺无法由公开 API 实现的“后台监听所有应用登录成功”，策划和商店描述均如实说明。

这个边界不是削减产品质量，而是避免做一个表面上自动、实质上靠监听用户界面的高风险功能。

## 6. 权限计划

原则：最少权限，能不申请就不申请。

- 网络：不申请。
- 相机：仅用户选择扫描 TOTP 二维码时，通过 Scan Kit 使用；优先采用系统默认扫码界面。
- 麦克风：仅用户在日记中点击录音时申请；拒绝只禁用录音，不影响其他功能。
- 图库：日记配图通过系统图库选择器（PhotoViewPicker）选取，接口本身无需申请相册权限。
- 剪贴板读取：不申请；本应用只写入并清理自己写入的数据。
- 文件：仅用系统文件选择器做 `.zvault` 导入/导出，以及导出日记录音和配图，不申请宽泛存储权限，也不获取删除他人文件的能力。
- 生物认证：通过系统 User Authentication Kit 拉起标准系统认证界面。
- 通知：当前完整发行范围不申请，避免 TOTP 等秘密出现在通知中心。

设置页提供“权限与隐私”清单，逐项解释用途与当前状态。

### 8.1 二维码专项发布门槛

二维码不能只重复点同一个按钮 20 次，而要覆盖至少 20 个不同风险场景。以下 20 项全部通过才允许发布：

1. 普通 ASCII 文本生成并被另一台真机正确识别。
2. 中文、英文、数字混合文本往返一致。
3. 多行文本、空格、制表符和换行保持一致。
4. URL 的查询参数、`#`、`&`、百分号编码保持一致。
5. WiFi WPA/WPA2 普通名称和密码可连接。
6. WiFi SSID 含中文、空格、分号、冒号、逗号和反斜杠时正确转义。
7. WiFi 密码含全部特殊字符时正确转义。
8. 隐藏 WiFi 的 `H:true` 正确。
9. 无密码 WiFi 格式正确且先向用户确认风险。
10. vCard 中文姓名、电话和邮箱可被系统联系人识别。
11. 空内容在调用 Scan Kit 前被拦截。
12. 超长内容在调用前提示缩短，不崩溃、不假死。
13. 低对比度颜色被拦截，高对比度深浅主题均可扫描。
14. 200、400、800 像素码图及不同纠错等级均清晰。
15. 手机竖屏、横屏、分屏和大字体下二维码不被裁切。
16. 平板和 2in1/电脑不同窗口尺寸下二维码保持正方形。
17. 模拟器首次进入显示指定弹窗，不调用后续生成、不闪退。
18. 模拟器连续进入、退出二维码页 100 次，无崩溃、无内存持续增长。
19. 真机连续生成、替换内容、旋转和退出 100 次，`PixelMap` 正确释放。
20. 生成过程中锁屏、切后台、关闭页面或销毁 Ability，异步回调不更新已销毁页面。

附加检查：

- 至少在 Phone 和 Tablet 真机互扫；2in1/PC 有可用真机时追加验证。
- 测试环境用非敏感固定样本做自动识别回读；真实密码二维码不落盘用于自检。
- Scan Kit 的同步异常、Promise 拒绝、回调错误都必须有自动化测试。
- 模拟器“不支持码图生成”属于预期能力差异，测试报告记为“已正确降级”，不能记为应用崩溃。

### 8.2 加密导出专项发布门槛（证明“真加密”）

`.zvault` 导出必须通过以下客观检查才允许发布：

1. 明文零残留：导出含已知样本（特定用户名、密码、日记片段）的保险库后，对整个 `.zvault` 做十六进制/字节搜索，样本明文零命中。
2. 头部最小化：明文文件头只含魔数、版本、KDF 参数、随机盐、随机 nonce，不含条目数量、名称、时间等可推断信息。
3. 随机性：同一份数据、同一密码两次导出，因随机盐/nonce 不同，密文完全不同。
4. 错误密码必败：错误导出密码解密必定失败，不产生任何部分明文。
5. 篡改必败：翻转密文任意 1 字节，GCM 校验必败并拒绝导入。
6. 跨端一致：手机导出的 `.zvault` 在平板、2in1/电脑正确导入且内容一致。
7. 算法核对：单元测试用标准测试向量校验 AES-256-GCM 与 PBKDF2 实现正确。
8. 普通导出对照：照片、录音的“普通导出”产物是可被系统正常打开的原格式文件，且界面已提示“该文件不再受本应用加密保护”。

只要任一项不达标，视为“加密未达真加密标准”，不予发布。

审批通过后按以下顺序在内部推进，但不会交付半成品；全部阶段完成并通过最终验收后，一次性交付完整项目：

1. 工程基础：新业务分支、设计令牌、响应式导航、数据库迁移框架、日志红线。
2. 安全内核：HUKS、Asset Store、DEK 多钥匙包裹、主密码、双重验证与私密问题重置、用户认证、生命周期锁定。
3. 核心保险库：条目模型、新增/查看/编辑/删除、修改历史与恢复、分类、搜索、收藏、回收站。
4. 专业能力：生成器、TOTP、WiFi 二维码、快速二维码、安全检查、剪贴板保护。
5. 内容扩展：加密日记本、日记录音、日记配图与应用内查看。
6. 高级安全：单条二次认证、伪装库、跨端加密导出与导入。
7. 三端精修：手机、平板、2in1/电脑布局、鼠标键盘与多窗。
8. 发布收尾：安全审计、自动化测试、性能、无障碍、商店素材和签名包。

6. 忘记 App 内置密码的默认重置方式是否为“双重设备验证”，并允许用户额外开启“自定义私密问题”。

只有本策划经确认后，才开始实现代码。后续功能变化继续先更新策划和验收标准，再进入开发。
